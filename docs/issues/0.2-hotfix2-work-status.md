The APK contains stripped game and renderer binaries. The older source archive
does not match this complete engine build, and the renderer audit found missing
custom patch sources. No unused asset scheduler, no-op optimization switches,
or unrelated port offsets are included to imply these missing integrations exist.

Related-port implementation references are recorded in
[PORT-SUGGESTIONS.md](../../modifications/v0.2/PORT-SUGGESTIONS.md). Designs in
other engines are investigation leads, not evidence of XHYN performance gains.

## User-requested controls

- Render scale is selectable from **0 to 100%**. Zero restores recorded game
  dimensions and removes XHYN's resolution override. Positive values scale the
  stored base size, with even dimensions and the existing 320 × 180 minimum.
  The dialog shows the actual dimensions, including when the minimum applies.
- Graphics quality has both a combined reset and individual **Restore default**
  actions. Original attribute values are recorded before changes in this update.
  Earlier releases did not record their originals; values already overwritten
  before this update cannot be recovered automatically. Unrelated XML settings
  and game saves are retained.
- **Edit dxvk.conf** and **View effective configuration** use the same selected
  game root and the same active text. Unchanged generated fields remain managed
  after saving, so later FPS/frame-generation settings continue to work. Comments,
  executable sections and explicit edited values are retained. Saving enables
  overrides; cancel preserves the original saved text.
- **DXVK tuning** exposes supported memory, shader, filtering, cache and advanced
  compatibility controls, with custom memory values and global reset. Buttons,
  editor and effective text update together. Specialized controls start collapsed;
  information buttons explain purpose and potential performance tradeoffs here
  and on graphics/performance/driver/diagnostic controls. The experimental DX10.1
  option limits exposed feature level, still requires Vulkan and may prevent
  startup. It does not add a native D3D10 backend. See the
  [complete tuning guide](../../modifications/v0.2/DXVK-TUNING.md).
- Diagnostics provides **Record next game → reproduce the problem → Save report
  to share**, with an automatic 20-minute limit. Technical details and original
  diagnostic actions remain available under advanced controls.

## Measurement limits

The optional observer is installed before the game starts only when recording or
experimental hints are requested. It guards the exact original loader entry
bytes, preserves the selected loader/BC dispatch and forwards original parameters,
allocation callbacks and Vulkan results. It does not change feature bits,
barriers, allocation sizes, transfers, rendering passes or resource lifetimes.

Tables are bounded: the first Vulkan instance, eight devices, 64 queues and 16,384
memory records. Other instances/devices continue through the original dispatch.
Allocation totals exclude unobserved contexts, suballocation details and earlier
allocations. Overflow is reported. Driver heap budget/usage are not process-owned
memory. Timing samples describe presentation calls, can include generated frames
and errors, and are not rendered-frame or GPU execution times. Percentiles use
the retained interval window. Pipeline time is wall time inside the API call.

Host tests, sanitizer checks, ARM64 ABI emulation and Android-view tests check
specific paths. They cannot qualify GPU execution or sustained gameplay. Hotfix 2
remains a development prerelease; unimplemented engine work and older crashes
are explicitly outstanding.
